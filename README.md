# 飲食店運営アプリ — 個人版

[アプリを開く](https://longchanp7-hub.github.io/restaurant-ops-app/)

端末のブラウザーに業務データを保存する、日本語の店舗運営アプリです。実データやバックアップをGitHubに保存する仕組みはありません。架空の売上・固定通知件数は表示しません。

## 最初に使う順序

1. **設定**で店舗名、席数、営業時間、月間売上目標を登録。
2. **スタッフ・メニュー・在庫**で基礎データを登録。在庫の「開始日・開始時の数量」は運用開始時点の残高です。
3. **売上・シフト・入出庫**を記録し、保存。
4. **レポート・会計・カレンダー**で記録を確認。
5. 作業後、**設定 → JSONバックアップを保存**。ダウンロード完了を確認し、端末外にも安全に保管。

各画面は追加・詳細・編集・状態変更に対応します。業務記録は保存ボタンを押すまで保存しません。未保存の入力を閉じる際は破棄確認を表示します。すべての営業日・予定時刻は日本時間、金額は税込の日本円として扱います。

### 外部接続と個人版の範囲

- SNS・LINEへの自動投稿・通知送信、AI実行、外部予約やカレンダーの同期は**未接続**です。URL保存は認証や連携開始を意味しません。「手動対応済」は利用者が手動で行った作業の記録です。
- 有料契約、APIキー、アカウント作成は不要です。APIキー・パスワードをメモに保存しないでください。
- ログイン・スタッフ共有・権限管理・複数店舗・端末間自動同期・端末内データの暗号化はありません。端末の共有には注意してください。
- 会計は簡易な記録・集計です。複式簿記、給与計算、税務申告は対象外です。シフトの金額は基本時給による参考額で、割増・控除を含みません。
- 売上から在庫は自動減算しません。仕入から経費、勤務から給与経費も自動登録しません。二重計上を避け、実際の入出庫と支払を別途入力してください。
- 予約は同日内、勤務は最大24時間です。在庫数量は小数3桁まで、円の金額は整数です。
- PWA用マニフェストは維持していますが、オフライン起動・プッシュ通知は保証しません。

## 保存と復元

- 業務データは `restaurantOpsData.v1` に、ホーム配置は従来どおり `restaurantOpsHome.v3` に分離。以前の配置を自動上書きしません。
- データは**端末・ブラウザー・サイトの保存領域ごと**に独立しています。別のブラウザー、シークレットモード、別端末では同じデータは見えません。ブラウザーのデータ削除や端末故障で失われます。
- JSONバックアップには業務記録・店舗設定・外部リンク・通知の確認状態を含みます。**ホーム配置は含みません**。CSVは閲覧・集計用で、復元には使えません。
- 復元はファイル形式、バージョン、日付・金額、参照先、勤務重複、在庫整合性を検証し、件数と店舗を表示します。確認後、現在の業務データ全体を置き換えます。
- 置換前の元データを `restaurantOpsData.v1.beforeRestore` に1世代だけ保存します。復元前には手元にもJSONをダウンロードしてください。安全コピーは次の復元で更新されるため、長期バックアップではありません。
- 書き込み失敗では既存の業務データを変更せず、入力を画面に残します。復元前コピーの保存に失敗した場合も復元を中止します。
- 壊れた保存データや未対応バージョンは自動初期化せず、書き込みを停止。「現在の元データを書き出す」で保全し、正常なバックアップから復元できます。
- 別タブの変更を検出した場合、入力を控えてから設定の「保存データを再読込」を使用します。Web Locks対応ブラウザーでは同時書き込みを直列化します。非対応環境では同時編集を避け、1タブで利用してください。
- 記録は完全削除せず、取消・退職・休止等の状態で残します。不要な個人情報は連絡先やメモを編集して空欄にできます。

## ホーム画面

既存のiPhone風4列グリッド、背景、長押し編集、ドラッグ並べ替え、非表示・再追加を維持します。下部Dock、検索ピル、ページドットは追加しません。ホームの「配置リセット」は業務データに影響しません。

## ローカル起動と検証

Node.js 22以降で、ランタイム依存パッケージなしに起動できます。

```sh
node scripts/serve.cjs
# http://127.0.0.1:4173
node --test tests/*.test.cjs
```

ブラウザーテストのみPlaywrightを使います。1ブラウザーで順番に実行し、実ユーザーのブラウザープロファイルやデータには触れません。

```sh
npm install --ignore-scripts
npx playwright install chromium
npm run test:browser
```

既存のEdgeで試す場合は環境変数 `BROWSER_CHANNEL=msedge` を指定できます。`EVIDENCE_DIR` は検証画像の保存先、`APP_URL` は検証対象のURLです。公開版を対象にしても、テストデータは使い捨てのブラウザープロファイル内だけに保存されます。

### 構成

- `app.js` / `home-state.js`: 既存ホーム操作。業務UIへの入口のみ追加。
- `ops-model.js`: データ定義・検証・保存アダプター・集計。DOMに依存せず、将来の共有バックエンドへ置き換える境界。
- `ops-ui.js` / `ops.css`: 業務画面と操作。
- `tests/`: 保存失敗・復元・境界値・集計・ホーム互換性、ブラウザーでの入力・再読込・復元・スマホ幅・ドラッグのテスト。
- `scripts/build-site.cjs`: 公開に必要な10ファイルだけを新しい `dist/` に出力。

## 公開

mainの更新でGitHub Pagesへデプロイします。公開成果物は `dist/` の許可済みアプリ資産だけです。バックアップ、CSV、テスト画像、ソース管理情報を公開成果物に含めません。PRではデータモデルとブラウザーの検証を実行します。
